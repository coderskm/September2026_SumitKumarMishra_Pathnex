K8s topics studied today -->

1} EKS Version management :-
1> EKS supports standard version and extended version.
2> standard version is supported till 14 months with charge of $0.10/hr
3> after 14 months if version not updated in old version only its supported in extended version with charge of $0.60/hr
4> but in extended version also old version supported till 12 months extra even with $0.60/hr charge

2} principle for different Kubernetes versions in different environments :-
1> Dev -> N+2
2> QA -> N+1
3> Staging -> N+1
4> Prod -> N  

N represents current version of Kubernetes running on prod.

3} If Kubernetes is updated, check whether addons are compatible with this new version or not.

4} addons can be rolled back to older version but cluster can never be rolled back to older version.

5} upgrading EKS cluster :- https://www.fairwinds.com/blog/guide-securely-upgrading-eks-clusters

7} Costly services in AWS :-
1> EC2 / EKS	2> RDS / Aurora	    3>S3, EBS etc
4> EKS has its own cluster fee but rest of the cost comes from infrastructure surrounding EKS like load balancer, NAT gateways and EC2 worker nodes.

8} Basic Configuration :- 
1> ReplicaSets -> created automatically.
2> Pods -> created after replicasets are created.
3> create node groups to create nodes.
4> node groups automatically creates auto scaling groups.
5> inside auto scaling group we can set how many nodes we want :- desired , maximum and minimum
6> nodes are nothing but EC2 instances. 

9} Inside Worker Node's EC2 Instance :-
1> check for kubelet status -> sudo systemctl status kubelet
2> check for kube-proxy status -> ps aux | grep kube-proxy

10} Steps to connect to Kubernetes :-
1. we need AWS credentials to connect to AWS EKS from our local machine.
2. once connected we can get access to k8s config file.
3. command to update local kubectl config to connect to AWS EKS -> aws eks update-kubeconfig --region ap-south-1 --name Pathnex.

12} namespaces in Kubernetes ->
1. Its used to divide Kubernetes cluster into different environments.
2. inside these environment different pods run. 
3. namespaces are logically separated from each other

13} cluster -> namespace -> Deployment -> ReplicaSet -> Pods -> Container

14} DaemonSet ->
1. It helps to make sure a particular pod runs on each node when a node is created, it immediately creates a copy of pod on it.
2. Helps node to run node level tasks such as logging, monitoring.

15} ReplicaSet in Kubernetes ->
Its used to maintain a specific number of pods that should always be running at any given time.
